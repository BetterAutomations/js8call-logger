Things knowingly not built yet. Newest at the top.

SOURCES
- RTL-SDR input is built (`sdr on`, `sdr --probe`, `--gain/--ppm/--serial`);
  rtl_fm | pacat into the cable with -E direct2 below 24 MHz, supervised with
  backoff, and the DVB-driver case explained in an event. Untested with a real
  dongle (no hardware yet); the plumbing is covered by stub-executable tests.
- USB sound card line input: selectable now (`input NAME`, `input --list`),
  and `level`, `doctor` and `clock --bootstrap` all follow the chosen device
  instead of the cable. Exercised against real ALSA capture devices on this
  machine (a mic with nothing plugged in reports digital silence, correctly).
  Still untested: an actual receiver feeding the card, and hot-plug (the device
  name changes with the USB port on some cards).

TUNING
- Band scan/hop for SDR sources: step the JS8 calling frequencies
  (3.578 / 7.078 / 10.130 / 14.078 / 18.104 / 21.078 / 24.922 / 28.078 MHz),
  score candidates by decodes per minute, keep the best. Needs an SDR we can
  retune; useless for a WebSDR tap or a line input, where the receiver is the
  operator's.
- Decode-depth tuning is built (`tune --decoder`, see README and DESIGN), but
  it was measured on one clean frame on a fast CPU: no difference between
  profiles at the decode edge. Re-run it on the SU9300 against real signals
  before trusting any of its verdicts there.
- Decode sweep is automated at start (`decode_auto`, `decode_auto_days`,
  `decode_auto_levels`): pauses loops, sweeps one level, applies only a >10 %
  win. Not done: running it mid-run, and sweeping when the input is a sound
  card (no way to inject the fixture).
- Notification is built for repair events (watchdog restart, cable rebuild,
  dial restore): a # line in the daily text, the daemon log, notify-send, and
  a status line. Not done: rate-limiting a fault that repeats for hours, and
  sending it anywhere off the machine (mail, MQTT).

CLOCK
- clock --set is built (needs root); untested against a real clock error.
- Continuous slew: deliberately not built; it fights systemd-timesyncd and
  moving the clock under a running JS8Call upsets its slot scheduler.
- Bootstrap is built (`clock --bootstrap`): spectral-peak correlation against
  the 15 s grid, refuses below 1.2x frame-vs-gap structure. Limits, measured:
  needs a strong isolated signal (fixture 3500x, busy 20 m band 1.14x), and
  ~1 s of the phase is audio pipeline delay. Not built: applying it
  automatically from the watchdog when nothing has decoded yet, and correcting
  the pipeline delay by measuring it against a known transmission.
- Absolute date/time cannot come from JS8 at all (frames carry sub-15 s
  phase, not a date). If that is ever needed, it is a GPS puck, not this.

PACKAGING
- GLIBC fallback build (JS8Call 2.5.2 / Qt5 / PortAudio) for distros older
  than glibc 2.38. Not needed for the target machine (Lubuntu 26.10).
- Flatpak, as morse-logger eventually wants.
